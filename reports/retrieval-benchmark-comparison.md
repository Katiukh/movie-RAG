# Сравнение качества retrieval и LLM-фильтра

Запуски от 2026-10-02 на одном корпусе из 500 фильмов и одном gold из 50 запросов.
Сравниваются BM25, Dense (BGE-M3), Hybrid (BM25 + BGE-M3 / RRF),
Hybrid + BGE reranker и тот же pipeline с локальным LLM-фильтром `qwen3:8b`.
LLM даёт лучшие Recall@1/3/5 overall и на semantic; reranker сохраняет лучший
Recall@10. При K=20 Dense лидирует overall и на semantic. На near_exact
и paraphrase LLM сохраняет показатели reranker. Совпадающие максимумы выделены вместе.

## Условия оценки

Relevant IDs определены по содержимому корпуса, до оценки retrieval.
[Gold и методика разметки](../data/eval/README.md) содержат основания positives
и ограничения выборки. Индексируемые поля: `title + what + about + why`.
LLM дополнительно получает `not_for` и выбирает только IDs; текст карточек
берётся из corpus. Gold и retrieval pipeline при добавлении LLM не менялись.

| Тип запроса | Запросов | С одним relevant document | С 2–5 relevant documents |
| --- | ---: | ---: | ---: |
| near_exact | 10 | 10 | 0 |
| paraphrase | 25 | 25 | 0 |
| semantic | 15 | 6 | 9 |
| **overall** | **50** | **41** | **9** |

Среднее число relevant documents на запрос — **1.34**.

`Recall@K = |relevant_ids ∩ retrieved_ids[:K]| / |relevant_ids|`.
Считаются уникальные попадания; overall и каждый тип — среднее по запросам
(macro average). Каждый запрос имеет одинаковый вес. Поэтому overall учитывает
размеры групп 10/25/15 и не равен простому среднему трёх групп.
Значения округлены до трёх знаков; выделение максимумов и разности вычислены
по исходным значениям без округления.

| Режим | Модель и параметры |
| --- | --- |
| BM25 | Существующий BM25Okapi и tokenizer проекта |
| Dense | `BAAI/bge-m3`; существующий кэш embeddings; batch size 8 |
| Hybrid | BM25 + BGE-M3; RRF k=60; по 20 кандидатов из каждого поиска |
| Hybrid + Reranker | 20 кандидатов Hybrid; `BAAI/bge-reranker-v2-m3`; batch size 4; max length 512; CUDA |
| Hybrid + Reranker + LLM | top-10 после того же reranker; локальный Ollama `qwen3:8b`; один вызов на запрос; `selected_ids`; temperature 0.2; think=false; num_ctx=8192; num_predict=4096; timeout 60 с |

## Overall — 50 запросов

| Режим | Recall@1 | Recall@3 | Recall@5 | Recall@10 | Recall@20 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 | 0.352 | 0.432 | 0.516 | 0.590 | 0.620 |
| Dense | 0.581 | 0.733 | 0.800 | 0.865 | **0.932** |
| Hybrid | 0.586 | 0.712 | 0.801 | 0.872 | 0.922 |
| Hybrid + Reranker | 0.841 | 0.890 | 0.890 | **0.917** | 0.922 |
| Hybrid + Reranker + LLM | **0.852** | **0.893** | **0.897** | 0.897 | — |

Reranker повышает Recall@1 с 0.586 у Hybrid до 0.841, а Recall@10 —
с 0.872 до 0.917. При переходе Dense → Hybrid результат зависит от K:
Recall@3 снижается, тогда как Recall@1/5/10 растёт.
При K=20 Dense достигает 0.932, опережая Hybrid и reranker (оба 0.922).

## semantic — 15 запросов

| Режим | Recall@1 | Recall@3 | Recall@5 | Recall@10 | Recall@20 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 | 0.374 | 0.441 | 0.454 | 0.499 | 0.532 |
| Dense | 0.336 | 0.577 | 0.599 | 0.682 | **0.840** |
| Hybrid | 0.352 | 0.508 | 0.669 | 0.773 | 0.807 |
| Hybrid + Reranker | 0.536 | 0.699 | 0.699 | **0.790** | 0.807 |
| Hybrid + Reranker + LLM | **0.574** | **0.710** | **0.723** | 0.723 | — |

Hybrid улучшает Recall@10 относительно Dense с 0.682 до 0.773
(+9.11 п.п.), но уступает при K=3. BM25 превосходит Dense и Hybrid
при K=1; при K=3/5/10 оба режима с embeddings лучше BM25.
Reranker повышает Recall@1 относительно Hybrid на 18.33 п.п.,
а Recall@10 — на 1.67 п.п.: здесь основной выигрыш приходится
на первые позиции выдачи. При K=20 Dense получает 0.840, а Hybrid
и reranker — 0.807: лидерство Hybrid над Dense при K=10 не сохраняется
на большей глубине.

Для запроса с N positives максимум Recall@1 равен 1/N. У этой semantic-группы
даже идеальный первый результат даёт средний Recall@1 **0.630**, а не 1.000,
поскольку 9 запросов имеют несколько релевантных фильмов. Overall имеет
соответствующий потолок Recall@1 **0.889**. Recall@10 может достигать 1.000,
так как число positives каждого запроса не превышает 5.

## Recall@20 и бюджеты reranker и LLM

Hybrid + Reranker переставляет ровно 20 кандидатов из Hybrid top-20.
При K=20 набор документов совпадает с Hybrid, поэтому Recall@20 одинаков
для каждого запроса и каждой группы. Reranker улучшает расположение positives
при меньших K, но не может вернуть документ вне этих 20 кандидатов.
Бюджет кандидатов reranker во всех запусках сохранён равным 20.

LLM получает только первые 10 после reranker, независимо от cutoff метрики,
и возвращает от 0 до 10 выбранных фильмов в прежнем порядке. Поэтому
для LLM в колонках Recall@20 и Δ Recall@20 стоят прочерки: модель не получает
кандидатов с позиций 11–20. Формально вычисленный Recall@20 дублирует
Recall@10 и не добавляет информации. Recall@10 сравнивает один и тот же
набор кандидатов до и после LLM.

## Результат LLM-фильтра

Overall Recall@1 вырос с 0.841 до 0.852 (+1.17 п.п.), а Recall@10 снизился
с 0.917 до 0.897 (−2.00 п.п.). На semantic соответствующие изменения —
+3.89 и −6.67 п.п. LLM улучшила первые позиции, но исключила часть gold positives.
В этом запуске выбирались 1–5 фильмов, в среднем 2.24 на запрос; пустых выдач
и ошибок API/validation не было. Каждый выбранный ID проверен как принадлежащий
прежнему reranker top-10; порядок не менялся.

| Query ID | Запрос | Recall@10 до → после | Исключённые positives |
| --- | --- | ---: | --- |
| q038 | анимационная история о героях-животных, сталкивающихся с жестокостью или опасностями | 1.000 → 0.667 | Удивительная история Мароны |
| q048 | роуд-муви о поездке ради встречи с отцом или матерью | 1.000 → 0.333 | До встречи на Венере; Несносный дед |

Это расхождение с фиксированным gold. Recall не измеряет precision и не доказывает
правильность каждого оставленного фильма. Prompt и разметка под результат
не подгонялись. [Подробный отчёт LLM](llm-benchmark-comparison.md) содержит
распределение числа рекомендаций и fingerprints. Модель использует temperature=0.2
без фиксированного seed: следующий запуск может дать другой выбор.

## Источники и воспроизведение

Таблицы используют прежние четыре реальных retrieval-запуска и добавленный
реальный прогон LLM на тех же 50 запросах, с `ks=[1, 3, 5, 10, 20]`.
Сохранены top-20 каждого retrieval backend и выбранные LLM IDs каждого запроса.
Разметка, retrieval и бюджет reranker не менялись; повторно вызывать остальные
модели для добавления строки LLM не потребовалось.

Артефакты запусков локальные и исключены из Git. Для повторной оценки

prompt и всех передаваемых corpus fields, включая `not_for`.

Выводы относятся к этой небольшой авторской выборке; независимая человеческая
экспертиза разметки пока не проводилась. Время работы и другие метрики здесь
не измеряются. [Ранее выполненная ручная проверка reranker](reranker-comparison.md)
использует другой набор из 12 запросов и описывает latency отдельно.
