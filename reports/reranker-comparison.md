# Hybrid vs BGE reranker

Ручная проверка 2026-09-29 на 12 запросах из ТЗ, без новой разметки или количественного benchmark.

Команда:

```bash
uv run python -m movie_rag.retrieval.reranker --output-json /tmp/movie-rag-reranker-comparison.json
```

Корпус: 500 фильмов; SHA-256: `7923abed09c70f461a1d0883054f32b8dac6d827397d645f588ee6b73738c359`.
Модель: `BAAI/bge-reranker-v2-m3`, revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`.
Устройство: NVIDIA GeForce RTX 5060 Ti (16 ГБ), CUDA, FP16.
Параметры: candidate_k=20, top_k=5, batch_size=4, max_length=512.
Hybrid использует неизменённые BM25 и BGE-M3 с RRF k=60; embeddings корпуса взяты из существующего кэша.

Каждая строка содержит один замер; первый запрос включает прогрев. Время загрузки моделей и первоначального скачивания исключено.
Reranking latency включает токенизацию, inference, возврат scores на CPU и сортировку.

Медиана по 12 запросам: Hybrid **14.6 мс**, reranker **107.3 мс**, сумма этапов **120.3 мс**.
Диапазон reranker: **90.8–343.9 мс**.

## Наблюдения и failure cases

Это качественный просмотр выдачи и полей `what/about/why` текущего корпуса;
оценки relevance не размечались, количественных выводов об улучшении нет.

| Запрос | Наблюдение |
|---|---|
| хоррор | «Страх» поднимается 3 → 1, «Хребет дьявола» 18 → 2 и «Маяк» 8 → 3: reranker извлекает кандидатов из глубины списка. |
| неглупый ужастик | Ухудшение: первой становится драма «Обнаженная» (17 → 1), «Несносный дед» — второй. «Пакетоголовый», у которого в корпусе прямо указан хоррор, опускается 1 → 5. |
| мрачный криминальный триллер | «Комната страха» сохраняет 1 → 1; «Убийца» поднимается 15 → 2. Четыре фильма из Hybrid top-5 сохраняются. |
| уютное осеннее кино | «Осенняя Соната» поднимается 2 → 1, «Девятые врата» уходит из top-5. Но семейная драма и триллер «Окно во двор» не гарантируют уютного настроения; надёжного решения mood-запроса нет. |
| одиночество | «Молчаливый друг» (9 → 1) и «Тяжёлый» (13 → 2) соответствуют описаниям одиночества в корпусе. Сильное лексическое совпадение «Мы все идём на всемирную выставку» опускается 2 → 5. |
| роуд-муви | В top-5 вернулись «Взрослые игры» (6 → 5), вытеснив дорожный триллер «Неистовый». Все пять фильмов теперь совпадают с исходной сильной BM25-пятёркой, хотя порядок другой; «Вне игры» 1 → 2. |
| программист хакер | «Сеть», непосредственно описанная как история программистки и хакеров, остаётся 1 → 1. Следующие результаты значительно менее точны. |
| что-нибудь странное про интернет | «Сеть» поднимается 4 → 1; «Пульс» опускается 2 → 5. Интернет-тема есть, но «странность» понимается ненадёжно. |
| медленное тревожное кино про одиночество | «Тяжёлый» 10 → 1 и «Молчаливый друг» 7 → 2 поднимают тематически подходящих кандидатов. Однако медитативность не равна тревожности, все оттенки запроса не гарантированы. |
| про человека, которому тяжело вернуться к нормальной жизни после войны | «Дом храбрых» сохраняет 1 → 1. Описание прямо соответствует запросу: солдаты после Ирака адаптируются к мирной жизни. Ниже есть шум: «Роковое искушение» происходит во время войны, а не после неё. |
| мрачная история о разваливающихся отношениях | «Развод Надера и Симин» поднимается 20 → 5, но первой становится «Мефисто» (17 → 1), чьё описание посвящено карьере актёра в нацистской Германии. Улучшение не однозначное. |
| дорожное кино про дружбу | Провал: «Влюблённые» (20 → 1) — романтическая история поездок на поезде, «Парни из деревенского ада» (18 → 2) — хоррор о дорожных рабочих. «Секс-драйв» (9 → 3) подходит лучше, но «Вне игры» выпадает из top-5. |

У многих запросов scores близки к нулю. Это не вероятность и не основание
вводить произвольный порог: модель обучена общей relevance, а разговорные
русские запросы о настроении и вкусе могут плохо соответствовать её задаче.
Reranker переставляет только Hybrid top-20 и не может вернуть фильм вне этого
candidate set. Изменений модели, tokenizer, весов RRF и ручных boost-правил
по результатам этих примеров не делалось.

## Дополнительные реальные проверки

- CPU, FP32, batch size 1: две пары из запроса про войну обработаны за **558,6 мс**
  при четырёх потоках PyTorch; загрузка модели из локального кэша — **3,88 с**.
  Это smoke check двух кандидатов, не сравнение производительности CPU/GPU
  на одинаковом candidate set.
